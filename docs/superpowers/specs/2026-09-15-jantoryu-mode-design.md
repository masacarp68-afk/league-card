# 雀竜位戦モード 設計

既存の「リーグ順位表 画像ジェネレーター」に、雀竜位戦のスプレッドシートを貼り付けて
同じデザインの順位表画像を作る「雀竜位戦」モードを追加する。

## 目的・前提

- 雀竜位戦のシートは「登録名／ポイント」のあとに各回戦の「得失点／順位／合計点」が並ぶ構造で、
  リーグ用パーサーでは各回戦の「順位」列（着順 1〜4）を順位として誤読してしまう
- 画像に載せるのは順位・名前・ポイントだけ。各回戦の点数は載せない
- 画像のデザイン（1920×1080・テーマ・ロゴ・色分け）は既存のまま流用する
- リーグ戦と雀竜位戦を画面上で切り替えられること

## 画面

- 上部に「リーグ戦／雀竜位戦」のラジオボタン。選んだモードは localStorage に記憶
- 設定（タイトル・節・全節数・全回戦数・色分け人数・テーマ・対局数表示）は **モードごとに別々に保存**
  - リーグ戦：`league-card.settings`（既存キーのまま。互換維持）
  - 雀竜位戦：`league-card.settings.jantoryu`
- 雀竜位戦モードでは
  - 貼り付けの案内文を「登録名／ポイント」の見出し行を含めてコピー、に変える
  - 色分けの見出しを「昇級（上位から）」→「通過（上位から）」、「降級（下位から）」→「敗退（下位から）」に変える
    （金・銀・銅／赤・薄赤の仕組み・入力欄 ID は同じ）
  - 初期値：タイトル `第○期 雀竜位戦【○次予選】`、節 `○回戦終了時`、全節数 0、全回戦数 6、通過 4、敗退 4
- モードを切り替えたら、そのモードの設定を入力欄に復元して再描画（貼り付け内容はそのまま）

## 雀竜位戦の読み取り（`parseJantoryu`）

- 入力は TSV。見出し行は **最初の数行から「登録名系」と「ポイント系」の両方を含む行** を探す
  （見出しの上に ①〜⑥ の行が混ざっていても読める。リーグ用パーサーも同じ探し方にする）
- 列の判定
  - 名前：`登録名` `選手名` `氏名` `名前`（必須）
  - ポイント：`ポイント` `トータル` `合計` `累計`（必須。**「合計点」は除外**）
  - 得失点：`得失点` を含む列すべて（任意。数値が入っている列数 = 対局数）
  - 「順位」列は無視する
- 行の扱い
  - 名前が空、またはポイントが数値でない行はスキップ（「供託」「check sum」行はこれで落ちる）
- 順位は **ポイントの高い順に並べ替えて付ける**。同点は同順位（1, 2, 2, 4 の方式）
- 出力はリーグ用と同じ形：`{ players: [{ rank, name, total, games }] }`
  - `games` は得失点の数値セル数。得失点列が1つも無ければ `null`

## 画像

- 描画は `renderStandings` をそのまま使う
- フッター：全節数が 0 のときは「全6回戦」のように `全` を付けて回戦数だけ表示
  （既存は「全12節・48回戦」。変更なし）

## ファイル

- `js/parse.js` … `parseJantoryu` 追加、見出し行の探索を共通化
- `js/app.js` … モード切替、モードごとの設定保存、案内文・見出しの差し替え
- `index.html` / `style.css` … 切替 UI
- `js/render.js` … フッターの「全」表記
- `test/parse.test.js` / `test/render.test.js` … テスト追加
- `README.md` … 雀竜位戦の使い方

## テスト

- `parseJantoryu`：見本シート（16人・6回戦・供託／check sum 行つき）を貼った結果が
  ポイント降順で順位付けされ、対局数が得失点の数から出ること。同点の順位。①〜⑥ 行が上にあっても読めること。
  「合計点」をポイントと誤判定しないこと。必須列が無いときのエラー
- `parseStandings`：見出し行の上に余計な行があっても読めること（既存テストは全て通ること）
- フッター表記は目視確認

## やらないこと

- 各回戦の点数・着順の表示
- 雀竜位戦専用のデザイン
